# `@solyx/core`

The trading domain every other package builds on: market rules (tick sizes, board and odd lots, trading sessions), candles and technical indicators, the `BrokerAdapter`, `MarketDataProvider`, `MarketDataStream`, `NewsSource`, `FundamentalsProvider`, `SentimentScorer`, `WebSearch`, `WebReader`, `MemoryStore` and `ResearchStore` contracts, the `checkOrder` risk checks, the `OrderDesk` order flow and the `ResearchDesk`, which keeps reports and scored forecasts.

## Boundaries

- Pure and cross-runtime: no I/O and no Node or DOM APIs, so every process imports it. Implementations of its contracts live in their own packages.
- Technical indicators are pure functions, one value per bar and `null` while warming up, so the charts and the agent read the same numbers.
- `./quote` reduces a listing's intraday bars to its newest session against the last close before it, so the symbols pane and the overview's heat map read the same numbers.
- `./sectors` lists the Taiwan Stock Exchange's own sector indices in its current classification and leaves out the indices that add sectors up, so no listing counts twice.
- `./news` derives stories and sentiment from stored records as pure functions, so the symbol page's gauge and the agent read the same numbers. Items of one channel whose titles match exactly, such as reprints and a thread's replies, form one story; sentiment is given overall and for the press and the crowd.
- `./web-search` is the web as every vendor must serve it: a search takes structured filters (kind, first day, hosts, market) that each vendor's module translates, and its results carry `Published` times already read on the market's calendar. Searching and reading are separate contracts, so a vendor that only searches can still serve one.
- `./memory` is what the agent keeps across conversations. Its description and body schemas refuse text that looks like a key, token or ID number, and the agent's writes and the user's edits both pass through them, so no memory stores a secret in plain text.
- `./fundamentals` is a listing's filed figures as every provider must serve them: a statement holds one quarter alone, in the market's currency, with the day its figures were public. Growth, margins, trailing EPS and the price-to-earnings multiple are pure functions here, so the agent cites what the app computed, and a past multiple is priced only against the results public on its day.
- `./research` is what the agent holds of a listing: a report (`./report`), which carries a view over quarters and is revised, every revision kept, and the forecasts (`./forecast`) made under it, each frozen once made and scored against what the price then did. A listing without a report takes no forecast, and a session takes one. The `ResearchDesk` stamps a forecast's anchor, the newest daily bar, and its report revision itself, so a forecast cannot choose what it is measured from, and stamps a report with the newest quarter public when it was revised: once a newer one is out, the listing takes no forecast until the report is revised. A forecast's scenarios are bands that hold every price of the horizon's close exactly once, so one always comes true and its probabilities can be scored; the horizon counts daily bars after the anchor rather than dates, so judging needs no calendar, and `judgeForecast` settles every tie that daily bars leave against the plan. `forecastTimeline` places those same sessions on a chart's time axis, so a path is drawn where its forecast is judged. A claim in either carries its source and the source's own words, and where the user set up a decisions model the desk has each read against its quote and refuses one whose quote says less than it asserts; a claim no model read is kept as unread. Neither a report nor a forecast reaches the `OrderDesk`. Their text passes the same secret check a memory's does.
