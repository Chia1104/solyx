# `@solyx/market-data`

Market data providers, one module per provider, each implementing `MarketDataProvider` from `@solyx/core/market-data`, and `./candle-cache`, which wraps any provider with the candle store from `@solyx/db/cache`.

## Boundaries

- Normalize units here: `Candle.volume` is shares and `Candle.time` is UTC seconds, with daily and longer bars at midnight exchange time. A closed daily bar carries the exchange's reference price where the source gives it, which Fugle does as the close less its change and Longbridge only through its forward-adjusted bars; it is set once the session closes, so the cache keeps it.
- Streaming uses the runtime's `WebSocket`. Call a provider's REST or WebSocket API directly instead of adding its SDK when the surface is small.
- `./fugle` and `./fubon` both call Fugle's market data API through `fugle-api.ts`: Fubon serves the same API under its own session tokens, so the two differ only in endpoints, credentials and plan. `./fubon` takes its token and endpoints from a `@solyx/brokers/fubon` session rather than loading the SDK itself, and streams from the Normal-mode endpoint, the only one with candles.
- Fugle's API covers Taiwan listings. Its history stops at the last close, so today's session comes from the intraday endpoint, and ranges of a year or more are split. Providers serve bars of a session or shorter: Fugle clips weekly and monthly bars to the requested range, so the desktop backend's market data module merges them from daily bars, for history and the live bar alike. It answers 404 for a range without sessions as well as for an unknown symbol, so a 404 empties only that request.
- The API also streams minute bars and depth over one WebSocket; Fugle's basic plan allows one connection and five subscriptions, each one symbol on one channel, so a symbol's bars (`candles`) and its depth (`aggregates`) take one each. Subscribing to bars returns the session so far as a snapshot, which also refills it after a reconnect, so subscriptions are kept as the sets of watched symbols rather than queued commands; depth replays nothing, so its first push comes with the next change. The REST quote and the stream's aggregates share one shape, which counts sizes in board lots. The server sends a heartbeat every 30 seconds, and refused credentials stop reconnecting.
- `./longbridge` reads US listings from Longbridge's quote server through the sign-in's one `@solyx/longbridge` client, which owns the connection, its protocol and the budget every Longbridge reader shares. A login without a securities account has no quota for history by date, so bars are the latest thousand of each interval, about four years of days, as traded in the regular session. Daily bars are read forward-adjusted too, and each one's reference is the close before carried by how far the adjustment stepped from that day to this; a step within the adjusted closes' rounding counts as none, so a day nothing happened on counts from the close before itself. Longbridge rounds its adjustment, so a split comes out within a few hundredths of a percent and a payout within a few cents, and one too small for that rounding is missed. A listing is named in traditional Chinese, with its English name beside. Quotes asked for in the same turn go out as one request, since one takes up to 500 symbols, and each alone where Longbridge lists not one of them, which fails them all. `readLongbridgeSecurities` reads, over HTTP, the one list of US listings Longbridge documents, those it trades overnight, which holds the exchange-listed stocks and ETFs. The module is also the US market's `TradingCalendarProvider`: Longbridge answers a month per request and lists the days that close early apart from the full ones. `./longbridge-stream` pushes live minute bars and books over the same connection, since Longbridge holds one per sign-in, up to 500 subscriptions: Longbridge pushes sales rather than bars, so each minute's bar is merged from the regular session's sales before the close, counting a sale's price and shares, its shares alone or nothing by the condition it was reported under, as Longbridge's SDK reads them; a watch starts from the session's bars so far and a book from a read, since a quote push carries no close before it. A connection that drops takes its subscriptions with it, so the stream starts every watch again from its bars.
- `./candle-cache` stores closed sessions only, since today's bars change until the close. Each series covers one contiguous date span that ends at its newest stored bar, so later days (holidays, or a session not yet published) are asked for again; a request past the span starts the series over. Intraday series keep the requested window, or the furthest back a request reached since the app started, so history a chart scrolled back to is not asked for again while it runs.
- Each provider module publishes its plans as `MarketDataPlan`s and takes the user's plan. Its REST budgets are enforced per instance with `@solyx/utils/rate-limit`, so callers keep one instance per credential and plan, and its stream takes as many symbols as the plan allows. A 429 retries for at most 10 seconds a time instead of hanging a chart.
