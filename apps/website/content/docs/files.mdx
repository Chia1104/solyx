Solyx keeps two folders: a config folder in your home, which you may edit by hand, and a data folder the app manages. **Settings → About** shows both, with **Show in Finder** or **Show in folder**.

## Each channel apart

A nightly and a development build keep folders of their own, so neither touches a stable install's settings, keys or databases.

| Build       | Config folder      | Data folder, macOS                            | Data folder, Windows      |
| ----------- | ------------------ | --------------------------------------------- | ------------------------- |
| Stable      | `~/.solyx`         | `~/Library/Application Support/Solyx`         | `%APPDATA%\Solyx`         |
| Nightly     | `~/.solyx-nightly` | `~/Library/Application Support/Solyx Nightly` | `%APPDATA%\Solyx Nightly` |
| Development | `~/.solyx-dev`     | `~/Library/Application Support/Solyx Dev`     | `%APPDATA%\Solyx Dev`     |

## The config folder

- **`config.json`** holds your settings. Solyx applies a saved edit without a restart, keeps entries it does not read, reads one that no longer parses as its default, and never overwrites a file with syntax errors.
- **`config.schema.json`**, which `config.json` names as its `$schema`, describes every entry, so an editor can check and complete the file. Solyx writes it afresh at start.
- **`AGENTS.md`**, **`mcp.json`** and **`skills/`** are what you write for the agent. [Extensions](/docs/agent/extensions).

| File                | Holds                                                                                        |
| ------------------- | -------------------------------------------------------------------------------------------- |
| `user.sqlite`       | The watchlist, proposals, the paper account and its fills, exits, scheduled tasks and themes |
| `research.sqlite`   | Reports and forecasts                                                                        |
| `memory.sqlite`     | The agent's memories                                                                         |
| `news.sqlite`       | Collected news and its readings                                                              |
| `agent.sqlite`      | Conversations                                                                                |
| `cache.sqlite`      | Candles and providers' answers kept for a while; safe to clear                               |
| `secrets.json`      | Keys, sign-ins and the trading mandate, encrypted by your operating system                   |
| `agent-workspaces/` | Each conversation's folder for shell commands                                                |
| `fubon/`            | Fubon's SDK logs                                                                             |
| `restore/`          | A restore waiting for the next start, and the files it replaced                              |

**Settings → Storage** shows how much each store holds and clears the candle cache, conversations, memory, news, research or the watchlist.

Solyx writes no log file of its own; only Fubon's SDK keeps logs, in `fubon/`. Solyx's logs go to the terminal, and to an [OTLP endpoint](/docs/setup/observability) if you name one.
