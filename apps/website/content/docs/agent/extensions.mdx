## Skills

A skill is a playbook the agent reads when it needs it, and you can call it as a `/` command. **Settings → Skills** lists yours, the built-in ones and shared ones, with **Open skills folder**.

<Steps>
  <Step>
    **Make a folder** under `~/.solyx/skills/`, named for the skill: lowercase letters, digits and single hyphens, up to 64 characters.
  </Step>
  <Step>
    **Write its `SKILL.md`,** with the same name and a description of when to use it:

    ```md title="~/.solyx/skills/earnings-week/SKILL.md"
    ---
    name: earnings-week
    description: Review a listing ahead of its quarterly report. Use when results are due within a week.
    ---

    1. Read the last eight quarters' revenue, margins and EPS.
    2. Compare the consensus the news reports with the trailing figures.
    3. …
    ```

  </Step>
  <Step>
    **Call it** as `/earnings-week` in the composer, or let the agent read it when its description fits.
  </Step>
</Steps>

| Frontmatter                      | Does                                          |
| -------------------------------- | --------------------------------------------- |
| `name`                           | Must equal the folder's name                  |
| `description`                    | Required, up to 1,024 characters              |
| `user-invocable: false`          | Hides it from `/`, so only the agent reads it |
| `disable-model-invocation: true` | Turns it off                                  |

Yours win over a built-in skill of the same name. Skills in `~/.agents/skills`, shared with other agents, are offered once you switch each on.

## Standing instructions

`~/.solyx/AGENTS.md` holds instructions the agent reads with every message, such as how you size positions or what you never trade. It appears under **Settings → Skills → Standing instructions**.

## MCP servers

`~/.solyx/mcp.json` connects MCP servers, in the `mcpServers` format Claude, Cursor and pi use. **Open mcp.json** under **Settings → MCP** creates it.

```json title="~/.solyx/mcp.json"
{
  "mcpServers": {
    "notes": {
      "command": "npx",
      "args": ["-y", "@example/notes-mcp"],
      "env": { "NOTES_TOKEN": "secret:NOTES_TOKEN" }
    },
    "docs": {
      "url": "https://mcp.example.com/mcp",
      "headers": { "Authorization": "secret:DOCS_KEY" }
    }
  }
}
```

- **A local server** takes `command`, with `args`, `env` and `cwd` if it needs them. It gets only `HOME`, `LOGNAME`, `PATH`, `SHELL`, `TERM` and `USER` from your environment.
- **A remote server** takes `url`, with `headers` if it needs them, or signs in from **Settings → MCP**.
- **`secret:NAME`** stands for a secret you enter under **Settings → MCP**, saved with your keys rather than in the file.

Each tool is **Off**, **Ask** or **Auto**: off, asks each time, or runs on its own. Tools start on **Ask**, and only those a server marks read-only can be set to **Auto**. The agent loads servers' tools as it needs them through a tool search, which matches English words.

## The shell

**Let the agent use the shell**, under **Settings → Skills**, lets the agent run commands on your computer, in bash or PowerShell, in a folder of its own for each conversation that goes when the conversation does. It is off by default and offered only while orders go to the paper account. There is no sandbox: a command has your access to your files and the network, so it waits for you unless the decisions model judges it harmless in **Allow for me**, or the conversation is in **Don't ask**.
