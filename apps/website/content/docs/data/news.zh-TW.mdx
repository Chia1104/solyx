## 來源 [#sources]

| 來源                   | 帶來什麼                                   | 需要         |
| ---------------------- | ------------------------------------------ | ------------ |
| 公開資訊觀測站重大訊息 | 台灣公司申報的內容，精確到分鐘             | 不需要       |
| 內部人轉讓             | 內部人申報的股權轉讓                       | 不需要       |
| PTT 股票板             | 提到這檔的文章，附推文數                   | 不需要       |
| 新聞媒體               | 提到這檔的報導                             | 網路搜尋金鑰 |
| Threads 與 X           | 台股的貼文（Threads）與美股代號的貼文（X） | 網路搜尋金鑰 |

在 PTT 上，「爆」算 +100 推，「XX」算 −100，X1 到 X9 算 −10 到 −90。

## 收集 [#collection]

- 預設每 72 小時收集一次每檔的新聞，每 24 小時收集一次每個主題的新聞；兩者都可以在 **設定 → 排程 → App 自己收集的資料** 更改。收集器每 30 分鐘檢查一次哪些已經到期。
- 一檔股票第一次收集時往回涵蓋 7 天，之後每次都與上一次重疊一天。
- 每個來源與管道每次最多帶回 10 則。
- 連續失敗三次的來源會暫停六小時，除非 Agent 主動要求它。

## 事件，而不是標題 [#stories-not-headlines]

同一件事的轉載與改寫，會歸併成一個事件：

<Steps>
  <Step>
    **標題相同**。在同一個管道上，去掉 `Re:` 與 `Fw:`
    後標題相同的，三天內會歸併。標題至少要有八個字元。
  </Step>
  <Step>
    **改寫轉述**。同一類發言者一天之內的標題，在拿掉這檔的代號、名稱與網站自己的標籤後，相鄰字對的重疊至少達較短那則的
    40%，就會歸併。
  </Step>
  <Step>
    **意思相同**。開啟嵌入模型時，來自不同網站、日期落在同一個交易日的項目，向量夠接近就會歸併：OpenAI
    的 `text-embedding-3-large`（1,024 維）餘弦相似度要達
    0.82，`qwen3-embedding:0.6b` 則是 0.89。
  </Step>
</Steps>

事件的代表是其中決策模型讀過的最早一則；其餘都是它的轉述。

## 判讀事件 [#reading-a-story]

決策模型根據標題、摘要、網站與網址，把每個事件讀一次，回答：

| 問題   | 答案                                             |
| ------ | ------------------------------------------------ |
| 關聯度 | 是否與這檔有關                                   |
| 立場   | 五個等級，從非常看空到非常看多                   |
| 類型   | 報導、評論或業配推廣                             |
| 主題   | 財報、財測、資本、法律、業務、分析師、市場或其他 |
| 發言者 | 公司、媒體、投資人、參考頁面或其他發言者         |

$$
\text{stance} = \sum_{\ell} P(\ell)\, w_\ell
\qquad
w = -1,\ -0.5,\ 0,\ 0.5,\ 1
$$

權重從非常看空到非常看多。

模型有相當把握時，發言者採它最可能的答案，否則採這個管道平常的發言者。關聯度達 0.5 以上，事件才算與這檔有關。

標題或摘要變動時，事件的判讀會清除並重新判讀；摘要只改了空白的，則保留原本的判讀。

## 情緒指標 [#the-gauge]

情緒指標把各事件的立場加總，每個都依關聯度、不像業配的程度與新舊程度加權：

$$
\begin{aligned}
\text{weight} &= \text{relevance} \times \bigl(1 - P(\text{promotion})\bigr) \times \text{fade} \\
\text{fade} &= 0.5^{\,\text{age} / \text{half-life}} \\
\text{score} &= \operatorname{round}\bigl((\text{weighted stance} + 1) \times 50\bigr)
\end{aligned}
$$

分數從 0 到 100，50 為中性。

| 發言者類別 | 半衰期 |
| ---------- | ------ |
| 新聞       | 2 天   |
| 社群       | 1 天   |

衰減後的權重低於 0.5 時，情緒指標會標示為近期資料不足。圖表上的每日情緒不會衰減。

## 排序重大消息 [#ranking-headlines]

$$
\begin{aligned}
\text{weight} &= \text{speaker} \times \text{reading} \times \log_2(1 + \text{items}) \times \text{fade} \\
\text{reading} &= \text{relevance} \times \bigl(1 - P(\text{promotion})\bigr) \times \text{topic} \times \frac{1 + \lvert \text{stance} \rvert}{2}
\end{aligned}
$$

其中 items 是這則故事包含的報導數。

| 發言者           | 權重 | 主題         | 權重 |
| ---------------- | ---- | ------------ | ---- |
| 公司             | 1    | 財報、財測   | 1    |
| 媒體、其他發言者 | 0.8  | 資本、法律   | 0.8  |
| 投資人           | 0.45 | 業務、分析師 | 0.6  |
| 參考頁面         | 0    | 市場、其他   | 0.3  |

尚未判讀的事件以 0.3 計。共用同一則項目，或代表的那則讀起來相近的事件，會顯示成一則重大消息。總覽顯示過去一週的八則重大消息，Agent 則讀取十五則。

## 新聞保留多久 [#how-long-news-is-kept]

新聞類的項目預設保留 90 天，社群類 30 天。兩者都可以在 **設定 → 儲存空間** 改成 30、90、180 或 365 天，或永久保留。項目從發布時間起算，沒有日期的則從被找到時起算；每天清理一次，縮短保留期限時則立即清理。

## 主題 [#themes]

主題每天用最多四組關鍵字搜尋新聞，第一次往回涵蓋 14 天，之後每次重疊一天。決策模型把最新的 20 則逐一對照每個觀察訊號讀一次；支持度達 0.6 以上，該則就標記為一項進展。Agent 對同一個主題每小時最多搜尋一次。

## 語意搜尋 [#search-by-meaning]

有嵌入模型時，Solyx 搜尋新聞、報告、預測與記憶，除了比對字詞也比對語意，並以倒數排名融合（reciprocal rank，k = 60）合併兩種排名。它只保留明顯高於其他結果的命中：比這次查詢的平均相似度高出 0.12。

| 嵌入的文字 | 使用的內容                                                       |
| ---------- | ---------------------------------------------------------------- |
| 一則新聞   | 標題，以及摘要的前 500 個字元                                    |
| 一筆記憶   | 描述與內文                                                       |
| 一份報告   | 論點、每個論點支撐、風險、反證條件、估值與事件，以及內文的每一句 |
| 一個預測   | 理由與反方論點的每一句，以及每個主張                             |

<Callout title="你自己的文字只交給本機嵌入模型">
  新聞可以由 OpenAI 或 Ollama 嵌入。報告、反證條件、記憶與你的搜尋，只由你設定的
  Ollama 端點嵌入，絕不交給 OpenAI。
</Callout>

使用 `qwen3-embedding:0.6b` 時，新的記憶與同類的某筆記憶相似度達 0.72，就視為重複，Agent 會被指向它已經有的那一筆。
