策略是你寫的程式：它從一檔股票的 K 線算出幾條線，再加上建立在這些線上的規則，由 Solyx 的引擎照規則交易。程式可以用你電腦能執行的任何語言。每筆交易的成交、價格與成本都由引擎決定，和[範本](/zh-TW/docs/backtests)一樣，所以策略和範本的量法完全相同。

策略放在[設定資料夾](/zh-TW/docs/files#the-config-folder)的 `strategies/` 裡，一個策略一個資料夾。Solyx 每次都重新讀取，所以改了之後，下次打開就看得到。

## 策略頁 [#the-strategies-page]

標題列 **設定** 旁的 **策略** 會列出你寫的每個策略：它依什麼買賣、可調的數字、這個版本能不能在這裡執行，不能的話原因是什麼，以及回測面板保留的最近一次回測。你可以在這裡選一檔持有、自選或輸入代號的個股回測，會開啟那檔的回測面板並選好這個策略；也可以請 Agent 寫新的或修改。這頁也會列出 `strategies/` 裡讀不了的資料夾和原因，以及策略程式在執行的地方找得到哪些直譯器。

每個策略自己的頁面，還有它的檔案、你允許過的版本、回測面板在各檔個股保留的紀錄，以及允許這個版本、撤銷所有允許、開啟資料夾、移到垃圾桶等按鈕。移到垃圾桶也會撤銷它的允許，所以放回來後要再允許一次。**用它的訊號交易** 會擬好請求，請 Agent 建立依它交易的[排程任務](#running-one)。配對的瀏覽器可以看這兩頁、也可以回測，其餘只能在電腦上做。Agent 不會刪除策略。

## 寫一個策略 [#writing-one]

`STRATEGY.md` 以 frontmatter 開頭，說明這是什麼策略，後面可以接著寫給你自己和 Agent 看的筆記：

```md title="STRATEGY.md"
---
name: atr-breakout
description: Buys a close above the last highs plus k average ranges, sells one under the average
run: python3 strategy.py
params:
  period: { min: 10, max: 60, step: 5, initial: 20 }
  k: { min: 0.5, max: 3, step: 0.5, initial: 1.5 }
rules:
  entry:
    crossesAbove: [{ line: close }, { line: upper }]
  exit:
    below: [{ line: close }, { line: trend }]
  stopLoss: 0.08
---

What the idea is, when it works and where it fails.
```

- **`name`**：資料夾的名稱，最多 64 個小寫英文字母、數字與單一連字號。
- **`description`**：一句話說它做什麼。
- **`run`**：在策略資料夾裡執行程式的指令。
- **`params`**：程式吃的數字，最多 8 個，各從 `min` 到 `max`、每次加 `step`，從 `initial` 開始。
- **`rules`**：`entry` 與 `exit`，寫法和 Agent 的 `backtest.rules` 相同，可另加 `stopLoss` 與 `takeProfit`。`{ line: name }` 讀取程式算出的一條線。

規則裡，策略的線只能和它的另一條線或一個 `value` 比較。程式拿到的價格以第一根 K 線為準、還原了分割與除權息，而 K 線本身的價格是實際成交價，兩者每逢分割就會分開。要和收盤價比，就把收盤價也當成一條線輸出。

## 和 Agent 一起寫 [#writing-one-with-the-agent]

可以直接用文字請 Agent 寫策略，也可以從策略頁的 **請 Agent 一起寫** 開始，或從回測面板開始：還沒有策略時，**我的策略** 底下有同樣的按鈕；範本或自訂規則跑完一次回測後，旁邊有 **存成我的策略**。`/strategy` 技能會讓 Agent：

- 先和你講好想法與每個數字要試的範圍，再看任何結果；
- 檢查程式在要執行的地方能用什麼：`PATH` 上有哪些直譯器，以及它的 Python 裝了 numpy、pandas、polars、scipy、TA-Lib 中的哪些；
- 寫好資料夾後，先檢查程式算出的線：App 有同樣的指標時就拿來對照，[前視檢查](#the-look-ahead-check)點名的線也要先修好，才開始回測；
- 照 `/backtest` 的方式回測，並說明它存過、測過幾個版本，因為在同一段 K 線上試的每個版本，都會用掉那段樣本外資料。

允許 Agent 存檔，就是允許它存出來的那個版本，所以卡片會把這個版本的檔案和你上次允許的版本並排比較；新策略則列出每個檔案。對話設為 **自動判斷** 時，新策略，或這段對話自己寫、之後沒人改過的策略，只要決策模型判斷程式無害，就會直接存檔；改你自己寫的策略一律會先問你。有實盤帳戶又在沙箱外時，只有你能允許版本。Agent 只會在策略資料夾裡寫文字檔，不會寫進工具放在程式旁的東西；它讀過之後檔案若又改了，存檔會被拒絕。

## 程式讀什麼、寫什麼 [#what-the-code-reads-and-writes]

程式從 `$SOLYX_STRATEGY_INPUT` 指定的檔案讀 JSON，寫 JSON 到 `$SOLYX_STRATEGY_OUTPUT` 指定的檔案。

輸入包含這檔股票、以欄位排列的 K 線，以及各個工作：每個工作是一組數字，跑在前若干根 K 線上。K 線的 `time` 是交易日的日期；比日 K 短的 K 線則是交易所時間的分鐘，例如 `2026-10-26 09:01`。

```json
{
  "symbol": { "market": "TW", "symbol": "2330" },
  "interval": "1d",
  "bars": {
    "time": ["2016-10-26", "…"],
    "open": [],
    "high": [],
    "low": [],
    "close": [],
    "volume": []
  },
  "jobs": [{ "id": "run0", "params": { "period": 20, "k": 1.5 }, "bars": 2529 }]
}
```

輸出以每個工作的 `id` 為鍵，放它的各條線，每根 K 線一個值，還沒有值的地方填 `null`。Python 的 `json` 寫出的 NaN 也當成沒有值。上面的策略用 Python 寫，`run` 是 `python3 strategy.py`；用 Node 寫則是 `node strategy.mjs`：

<Tabs items={["Python", "Node"]}>
<Tab value="Python">

```py title="strategy.py"
import json, os

data = json.load(open(os.environ["SOLYX_STRATEGY_INPUT"]))
output = {}

for job in data["jobs"]:
    n, k = int(job["params"]["period"]), job["params"]["k"]
    high = data["bars"]["high"][: job["bars"]]
    low = data["bars"]["low"][: job["bars"]]
    close = data["bars"]["close"][: job["bars"]]
    upper, trend = [], []

    for i in range(len(close)):
        if i < 2 * n:
            upper.append(None)
            trend.append(None)
            continue
        ranges = [high[j] - low[j] for j in range(i - n, i)]
        upper.append(max(high[i - n : i]) + k * sum(ranges) / n)
        trend.append(sum(close[i - 2 * n + 1 : i + 1]) / (2 * n))

    output[job["id"]] = {"close": close, "upper": upper, "trend": trend}

json.dump(output, open(os.environ["SOLYX_STRATEGY_OUTPUT"], "w"))
```

</Tab>
<Tab value="Node">

```js title="strategy.mjs"
import { readFileSync, writeFileSync } from "node:fs";

const data = JSON.parse(readFileSync(process.env.SOLYX_STRATEGY_INPUT, "utf8"));
const mean = (values) =>
  values.reduce((sum, value) => sum + value, 0) / values.length;
const output = {};

for (const job of data.jobs) {
  const { period: n, k } = job.params;
  const high = data.bars.high.slice(0, job.bars);
  const low = data.bars.low.slice(0, job.bars);
  const close = data.bars.close.slice(0, job.bars);
  const upper = [];
  const trend = [];

  for (let i = 0; i < close.length; i++) {
    if (i < 2 * n) {
      upper.push(null);
      trend.push(null);
      continue;
    }
    const ranges = high
      .slice(i - n, i)
      .map((value, j) => value - low[i - n + j]);
    upper.push(Math.max(...high.slice(i - n, i)) + k * mean(ranges));
    trend.push(mean(close.slice(i - 2 * n + 1, i + 1)));
  }

  output[job.id] = { close, upper, trend };
}

writeFileSync(process.env.SOLYX_STRATEGY_OUTPUT, JSON.stringify(output));
```

</Tab>
</Tabs>

掃參數時，一次執行就會交給程式所有的數字組合，所以要把每個工作分開算，並全部寫出。

## 程式在哪裡執行 [#where-the-code-runs]

每次執行都會把策略的檔案複製到一個專屬的資料夾，再執行那份複本，所以跑的一定是被允許的那個版本，不管資料夾之後變成什麼樣子。所有工作加起來有 2 分鐘。

- **在沙箱裡**：macOS 與 Linux 上，只要 **設定 → 程式執行 → 沙箱** 開著（除非你關閉，否則預設開啟），程式只能讀寫這次執行的資料夾、讀取 `PATH` 上的工具，也連不上任何網路，連你自己的電腦都不行。程式需要的套件請放在 `PATH` 上的環境裡，例如 venv 或 uv 的環境，因為沙箱會擋住家目錄裡的其他內容。
- **在沙箱外**：Windows 上，或關閉沙箱時，程式擁有你對檔案與網路的存取權。

一個策略資料夾最多 1,000 個檔案、32 MB，而且不能有連結，因為連結指向的內容可能改變，版本卻不變。

## 允許一個版本 [#allowing-a-version]

版本就是策略檔案的內容：任何一個檔案有任何改動，就是另一個版本，每個版本都要允許後才會執行。策略自己的頁面，以及個股圖表下方的 **回測**，遇到還沒允許的版本時，會提供 **看改了什麼**，列出每個檔案自上次允許的版本以來新增與刪除的行，以及 **允許這個版本**。配對的瀏覽器會請你在電腦上允許。

Agent 要執行還沒允許的版本時，它的呼叫會先問你，卡片上也列出同樣的改動。對話設為 **自動判斷** 時，由決策模型判斷程式：只有當它評估的每一項風險都不太可能發生，也就是程式不會動到自己以外的檔案、連上網路、讀取機密或啟動其他程式，這個版本才會不經詢問就執行。

有實盤帳戶時，策略的程式若在沙箱外執行，只會跑你親自允許的版本：決策模型與 **不詢問** 都無法在這種情況下允許。允許紀錄和你的金鑰一起加密保存，所以改動 App 的檔案無法允許任何版本。

程式是你的，它健不健全也由你負責：Solyx 盡可能把它關在沙箱裡、檢查能檢查的部分，但不會幫你找程式的錯誤。

## 前視檢查 [#the-look-ahead-check]

規則在一根 K 線收盤時判讀、在下一根開盤時執行，所以一條線只能來自它那根 K 線和之前的 K 線。你的程式一次拿到所有 K 線，所以 Solyx 會檢查：它用第一組數字，在前五分之一、五分之二、五分之三與五分之四的 K 線上各重跑一次，再把每條線和完整那次比較。

只要某條線不同，就表示程式算它時讀了之後的 K 線，像 `shift(-1)`、置中的視窗或整段期間的平均都會這樣。這次回測會以警示開頭，指出是哪條線、從哪根 K 線開始，因為這時每個數字都建立在當時不可能知道的價格上。這只是警示，不會拒絕執行。

## 執行策略 [#running-one]

- **在面板裡**：**策略 → 我的策略**，選策略，再設它的數字。掃參數與前進分析會沿著它的兩個數字跑網格。[回測](/zh-TW/docs/backtests)。
- **透過 Agent**：Agent 的腳本用 `strategies.backtest`、`strategies.scan`、`strategies.walkForward` 與 `strategies.rolling` 執行策略，和面板一樣；`strategies.signal` 則回答在最新一根 K 線收盤時，進場或出場條件是否成立，並附上同一段 K 線的回測在那時的部位。
- **用策略交易**：[排程任務](/zh-TW/docs/agent/schedules)可以在每個交易日收盤後讀取策略的訊號，讓 Agent 提出委託。它仍然只是提案：由你確認，或由你的交易授權送出。
