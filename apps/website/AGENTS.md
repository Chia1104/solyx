# `@solyx/website`

The project's website: the landing page and the docs, on TanStack Start and Fumadocs, prerendered and deployed to Cloudflare Workers through Void.

## Boundaries

- Every page is prerendered into `dist/client`, so a route that needs a server per request does not belong here. A loader reads what it needs where it runs, in the browser on client-side navigation, never through a server function: the Worker answers no navigation, and the prerender runs on workerd, where `staticFunctionMiddleware` cannot write its results to files. Search downloads the index `/api/search` exports and runs in the browser.
- `voidPlugin()` builds the site for the Workers runtime, Cloudflare serves the prerendered files, and the Worker answers only what no file matches. The Worker's settings, including its one domain `usesolyx.trade`, live in `void.config.ts`; `void.lock.json`, which pins the account and the Worker, is committed beside it.
- The site follows `develop`, not the latest release: every push to `develop` that changes what it is built from deploys it (`.github/workflows/website.yml`), so a page about a feature lands with that feature's code.
- The download page and the changelog read GitHub's releases once per build (`src/lib/releases.ts`), never from the browser, and Nightly and Release redeploy the site after they publish. The changelog is GitHub's generated notes, so a pull request's Conventional Commits title is its entry, grouped by type. Installers link to their GitHub release, since `download.usesolyx.trade` keeps only the newest nightly. The visitor's system is read only after hydration (`useVisitorPlatform`), so every prerendered page is the same for everyone.
- The crawler only follows links and each locale is prerendered on its own, so `vite.config.ts` lists every page in every locale for the prerender.
- Every page's social card is drawn by the client build in Node with Fumadocs' Takumi template from the same page list, into `dist/client/og`, and `src/lib/social-card.ts` gives its `og:image`. Neither the Worker nor a prerendered route draws one: TanStack Start's prerender writes a response as text, which breaks an image, and drawing would run past Workers Free's CPU time.
- Docs are MDX in `content/docs`, ordered by each folder's `meta.json`. They describe what the app does today, taken from its code and the root README, and change with the code they describe; a `data/` page changes with the `@solyx/core` code whose formulas, windows and limits it states.
- A docs page may use only the MDX components `src/components/mdx.tsx` registers. A list or table inside one is set off by blank lines from its tags, or the formatter reflows it into a paragraph. Formulas are KaTeX through `remark-math` and `rehype-katex`, between `$$` alone, since prose quotes prices such as NT$20; only docs pages load KaTeX's stylesheet.
- A screenshot is `<Screenshot file="…">`, the same name in every locale: a file under `content/docs/images`, or under `docs/` on `assets.usesolyx.trade`, an R2 bucket for what is too large for the repository; the repository's copy wins. A copy may carry a locale and a colour scheme as tags (`name.zh-TW.dark.png`), and the page shows the best fit, language before scheme; both schemes are drawn and the stylesheet shows one, since a prerendered page cannot know the reader's. The build asks the asset host once which shots it holds, so an upload shows from the next deploy, and a shot the host gives no answer for is offered anyway, so the host's trouble never fails the build. A shot that fails to load gives way to the next that fits, and once none is left a pencilled frame holds its place.
- The terms of use and the privacy policy are MDX in `content/legal`, through their own collection, at `/terms` and `/privacy` in each locale; the app links to them. The privacy policy names every place the app sends data and what each receives, so it changes, with its date, with any code that sends something new.
- The site sends nothing about its visitors: no analytics, fonts self-hosted through Fontsource, and the Shaders canvas runs with `disableTelemetry`.
- The site speaks the app's locales, `en-US` and `zh-TW` (`src/lib/i18n.ts`). English keeps the site's own paths and every other locale is the path's first segment (`/zh-TW/docs/...`), through TanStack Router's optional `{-$lang}` segment and Fumadocs' `hideLocale: "default-locale"`. `useLocale` reads the locale from the path, not a route's params, so an address no route matches still speaks its language.
- Copy lives in `@solyx/i18n`'s `website/` catalogs, with one i18next instance per locale, so pages prerendered side by side never share a language. The demo workspace's labels come from the app's own `desktop/` catalogs; its script returns data, not sentences, and the agent pane words it.
- A docs page in another locale is `name.<locale>.mdx` beside the English one, with links to its own locale's paths. Each heading ends with the English heading's id (`## 標題 [#english-id]`), so an anchor is the same in every locale. Search finds only pages in the language on screen.

## Theme and components

- `src/styles/app.css` sets the app's Blueprint palette as shadcn's tokens, which Fumadocs reads through its `shadcn.css` preset, so the docs and the landing page share one theme. Tokens shadcn has no name for (`--graphite`, `--hatch`, `--stipple`, `--rise`, `--fall`, the candles, the ink's gradient ends) sit beside them.
- Interactive pieces are shadcn's Base UI components in `src/components/ui`, added with the shadcn CLI (`components.json`, style `base-vega`) and edited in place. Where no shadcn component fits, use the Base UI primitive directly. A link styled as a button stays a link and takes `buttonVariants`. A link in running text takes the `link` utility, as Fumadocs draws links in the docs; a list of navigation links takes Fumadocs' header style.
- An address no route matches and a route that fails both show a `StatusSheet`, through the router's `defaultNotFoundComponent` and `defaultErrorComponent`. Retrying invalidates the router, which reloads the route and clears its error boundary.
- Motion uses the theme's `ease-out` and `ease-in-out`, which `app.css` redefines as strong curves. Reveals travel left to right, the way a pen moves. A loop runs only while its section is on screen (`useInView`). Under reduced motion only fades remain, and a loop shows its finished state, as it does before scripts run.

## Landing page

- It is drawn on the app's drafting sheet: hatching, stippling and dashed outlines are pencil, what the agent drafted, and the primary colour is ink, what the user signed.
- Below the hero, the page sits between the sheet's dashed rails (`Sheet`), each band ruled off by a `SheetRow`. Cells share hairlines instead of floating as cards, and only one is filled with ink. The site's own buttons are pills; the demo keeps the app's corners, since it shows the app.
- Confirming a proposal is the only button that fills with ink, as in the app, and only while it is held (`HoldButton`), so no `Button` takes the default variant.
- The hero's inked sun is drawn on a WebGPU canvas from `shaders`, loaded after the page since the engine carries every effect it offers; where WebGPU is missing, an SVG draws it at rest. Copy laid over it sits on a `scrim` so it stays legible. Canvases take the sheet's colours from the stylesheet through `useSheetColors`, so a theme change repaints them.
- The demo workspace runs on made-up prices from a fixed seed, so the server and the browser draw the same bars, and it fetches nothing. It reuses the app's domain-free or pure pieces: `@solyx/trading-chart` for the chart and `@solyx/core` for ticks, lots and indicators. Every price sits on its listing's tick, and a proposal stays inside the next session's limits, as the app's risk checks would demand.
- The model providers in `providers.tsx` are the agent's catalog as the app offers it: pi-ai's built-in providers less those `@solyx/agent`'s `models.ts` withholds, one per company, plus Ollama. They change with that catalog, and the web search vendors beside them with `@solyx/web-search`'s. The logos are lobe-icons', as in the app's settings.
