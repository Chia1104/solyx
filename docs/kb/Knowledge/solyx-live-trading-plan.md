# 2026-10-19 live trading: broker landscape, user's picks, stack #230→#233 (verified in Fubon test env, ready), test-env findings, next push events/Taishin/Shioaji

On 2026-10-19 the user asked (1) which other TW brokers Solyx could support, (2) how to allow full automation with permissions the user sets ("使用者自己判斷跟承擔"), (3) how to build live trading. Analysis only; nothing built.

Broker landscape (researched 2026-10-19):

- Fit the "user downloads SDK, app loads it from a path" pattern (napi-rs Node SDKs built by Fugle, not on npm): Fubon `fubon-neo` 2.4.0 (test env for stock accounts only; 50 orders/s, 5 account queries/s; `userDef` ≤10 alnum chars; `placeOrder(account, order, unblock)`; no 複委託), Taishin Nova `taishin-sdk` 1.0.2 (MIT, sync calls that throw, no simulation; Taishin absorbed Masterlink 2026-04-06; NOT a Fubon mirror — see below), E.SUN `@esun/trade` 2.2.0 (MIT, but imports native `keytar` + `inquirer`; simulation never fills).
- Shioaji: no Node SDK, but its standalone binary runs a user-started localhost HTTP + SSE server (optional API key since 1.7.8, 2026-10-13); Solyx would be a client.
- Yuanta SPARK needs .NET 8; KGI SUPER PY is Python only; Capital, Mega, President, Concords, First are Windows COM/DLL; Cathay has no public order API. No cross-platform TW SDK does US stocks.
- TWSE 「證券商受理投資人使用 API 服務作業規範」(105.06.01): investor declares they 自行決定買賣之執行 and won't let third parties/資訊廠商 do 全權委託; brokers set abnormal-behaviour criteria and may suspend API.

What I proposed (not confirmed): a separate user-set trading mandate (scope, per-day caps, expiry, circuit breakers into `trading.locked`, audit of which mandate sent each order), checked by the desk at propose time, rather than tying auto-confirm to a conversation's `auto` mode — agent-saved tasks default to `auto`, so that would let unattended runs trade. Paper first, then live in shadow mode. Live gaps: `BrokerAdapter` has no cancel, order query or event stream; `Submitted` is terminal; TW cash is the bank 交割戶 with T+2, so `AccountSnapshot.cash` isn't buying power; reconcile unknown outcomes via `userDef`. Suggested second broker: Taishin (cheap, mirrors Fubon) or Shioaji (largest base, simulation).

The user's picks (2026-10-19): (1) the mandate is its own grant, not the conversation's `auto`; (2) shadow mode is the user's setting, on by default; (3) build both Taishin and Shioaji as further brokers. I then started building stage A (live broker contract + read-only Fubon) as a stack.
